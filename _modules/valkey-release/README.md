# valkey-release

Installs the [Bitnami Valkey Helm chart](https://artifacthub.io/packages/helm/bitnami/valkey)
in-cluster via `helm_release`, bridging a Terraform-managed AUTH password
into a Kubernetes Secret the chart references by name (`auth.existingSecret`).

Used by the `prod/us-east-1/valkey` terragrunt unit to provide Zitadel's
Redis-compatible cache connector without a managed ElastiCache service --
mirrors `wp.lodge104.net`'s use of an in-cluster Bitnami Memcached sub-chart
instead of managed ElastiCache for its cache layer (see issue referenced in
`wp.lodge104.net`'s `_common/wordpress.hcl`).

Standalone architecture (single primary, no replicas/Sentinel) is sufficient
here: Zitadel's Redis cache connector only supports a single endpoint
anyway (no cluster-mode or Sentinel support), so replicas would add
operational cost without being usable.

## Providers

`helm` and `kubernetes` providers must be generated by the including
`terragrunt.hcl`; this module does not declare provider blocks itself.
